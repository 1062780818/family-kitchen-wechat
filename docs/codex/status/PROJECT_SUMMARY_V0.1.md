## 2. 三方一致结论

1. 固定基线是真实可运行的有条件复用候选，不是README壳：冻结依赖安装、shared／backend／小程序构建、13个数据库迁移、seed及原后端基础链路可以运行；但它没有实现已确认的固定夫妻权限、逐菜处理与调整确认、独立亲亲价格及送达记录等目标业务。
2. 当前代码不能作为发布候选：管理端生产构建失败18条TS诊断；根Lint／test不通过；后端148用例中46失败；typecheck存在漏检；图片可匿名读取。C03对C01基线报告给出`CONDITIONAL PASS`，对当前代码发布门禁给出`FAIL`，两者适用范围不同。
3. 微信／H5编译成功不等于真实微信闭环通过。三方都没有产品自有AppID、微信开发者工具、订阅模板、合法测试域名及夫妻双账号真机环境，因此登录、订阅通知、授权拒绝、断网回流和iOS／Android兼容仍待后续正式验收。

## 3. C01技术基线摘要

- 上游MIT许可证要求保留`Copyright (c) 2026 GuLu`、许可正文和免责条款；依赖及素材不能一律套用根MIT。MySQL服务端为GPLv2，MinIO服务端为AGPLv3，第三方图片素材仍需权属清理。
- 全依赖扫描记录critical 2／high 66／moderate 58／low 16；生产图为critical 1／high 43／moderate 32／low 4。计数是通告而非已证实漏洞，后续需按可达性修复和复验。
- 原版27项本机HTTP观察跑通家庭、多菜餐单、部分隔离、状态和历史；同时确认公开图片、弱配置、状态并发、WebSocket会话一致性及通知缺口等风险。
- 迁移历史可完整部署，但数据库与当前Prisma schema仍有字段长度和通知索引差异。本轮只生成只读diff，未修改迁移或业务代码。
- 架构条件性建议：优先保留NestJS＋Prisma＋MySQL可复用核心并先修工程／安全门禁；若产品明确不承担独立服务运维，再由ChatGPT另立CloudBase验证任务，不能由C01自行冻结。
