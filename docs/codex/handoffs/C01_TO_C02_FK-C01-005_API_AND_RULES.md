# C01→C02｜FK-C01-005规则与接口影响

读取`docs/codex/decisions/FK_CONFIRMED_REQUIREMENTS_V0.3.md`作为最新规则。19B、25B、36A、37A、30A均已确认，旧待决策不得继续展示。

## 已变化规则

- 丈夫建家并邀请妻子；加入确认后角色固定。只有丈夫管理正式菜及其图片、亲亲价格。
- 妻子待确认可直接改／取消；已接单只能提申请等丈夫同意；做饭中／已上菜不显示妻子改／取消。不同意换菜时原单和待确认状态不变。
- 亲亲价格默认1且只允许正整数；无分量、在线送达／支付。愿望菜独立，不进入餐单和合计。
- 预约今天至＋7天；同家庭／日期／餐次进行中餐单唯一；逐菜三档评价＋可选整单留言。

## 当前接口影响

- 图片上传仍为`POST /storage/upload?category=...`，响应`url`改为15分钟预览URL，必须持久化`key`而非`url`。读取用`GET /storage/url?key=...`，删除用`DELETE /storage/object?key=...`。
- `category=recipe`妻子会收到403；前端隐藏入口只是体验优化，服务端已经强制。愿望图片应使用独立非recipe分类（正式愿望分类待后端模型任务新增前可暂不接正式页面）。
- `POST /orders/:id/cancel`只有妻子在待确认状态可直接使用；已接单返回`ORDER_CHANGE_REQUEST_REQUIRED`。申请接口尚不存在，不要用直接取消模拟。
- 并发状态冲突返回`ORDER_VERSION_CONFLICT`，客户端应刷新当前餐单而非自动重试写操作。

## 仍需等待

目标餐位、亲亲价格快照、调整／取消申请、愿望和逐菜评价接口尚未实现；不要根据旧API自行拼接正式流程。亲亲最大值、每餐菜数、图片必填／数量、申请撤回／超时、评价修改／撤回和导航仍待后续决定。本文件写入不表示C02已启动，需外部正式启动后读取分支。
