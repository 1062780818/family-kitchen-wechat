# FK-C01-003｜问题去重与处理状态

更新时间：2026-09-07。来源包括C01、C02及C03的DR-01至DR-11。本文件只标记归属，不替用户或ChatGPT冻结未决业务。

## 一、用户已经确认

1. 第一版固定妻子为点菜者、丈夫为厨师；底层可扩展其他家人，但首版不显示复杂成员管理。
2. 每道正式菜可独立设置亲亲价格，默认1个；餐单保留下单价格快照；不做余额、欠账、充值、提现或真实支付。
3. 一餐支持多菜；支持预约日期、早餐／午餐／晚餐和预计开饭时间；支持小份／正常／大份、单菜备注和整单备注。
4. 厨师逐菜处理，可标记需要买菜、提议替换或拒绝；调整／删除／替换必须由妻子确认后才能正式接单。采购只做轻量备注，不做库存系统。
5. 菜单外菜可填写菜名、图片或参考链接；是否收入正式菜谱由丈夫决定。
6. 主状态为待确认、已接单、做饭中、已上菜；上菜后妻子点击送亲亲，动画不能代替服务端记录。
7. 评价选项为“很喜欢／还可以／下次不点”，留言可选。
8. 首批约20至30道菜由丈夫手机逐道录入；不做批量导入、AI识别或外链自动解析。

## 二、ChatGPT已经确定的技术规则

1. 重复点击、超时重试和并发请求不得重复生成同一次操作结果；请求幂等键须绑定可信身份、家庭和具体操作，重复键改变载荷应冲突。
2. 身份、固定角色、家庭归属、状态流转和价格计算由服务端／可信云函数验证，不能相信前端传值。
3. 历史名称和价格快照不能被当前菜谱覆盖；调整确认校验餐单版本，旧方案不能覆盖新方案。
4. 动画及客户端成功提示只能发生在服务端成功记录之后；通知失败不得倒置已成功的核心业务状态。
5. 安全实现细节可由ChatGPT在任务单冻结：危险协议拒绝、上传内容校验、内部错误码、私有图片经家庭授权读取、云端唯一约束／事务以及过期冲突响应。
