## 2. ChatGPT已冻结的技术要求

1. 餐单提交、调整提案和调整确认仍需幂等与并发保护；亲亲送达功能取消后，只删除其专属测试，不能删除其他重复请求保护。
2. 身份、角色、家庭、状态、价格及快照都由服务端／可信云函数校验；前端不能决定权威结果。
3. 当前菜价不得覆盖历史快照；调整确认必须校验餐单版本；客户端动画或提示不能代替服务端记录。
4. 同一餐位的唯一性建议由数据库唯一约束／占位记录或CloudBase确定性文档ID配合服务端事务保证；先查后写不满足并发要求。命中已存在餐单时返回可跳转的餐单标识。

## 4. 被覆盖的旧接口／数据／验收要求

- 删除候选：`portion`／`portionPrice`、愿望菜临时报价及餐单临时行、`kissDelivery`／送达确认／支付状态／亲亲流水、整单星级及自动评价。
- 保留候选：菜品`kissPrice`；餐单明细名称／价格快照；餐单亲亲合计；单菜和整单备注；餐单、调整、确认的请求幂等键及版本。
- 新独立边界：愿望清单与正式菜谱、餐单均不形成自动写入关系；逐菜评价关联餐单明细，整单留言独立可空；评价不改变餐单主状态。
- 验收删除：分量选择／加价、亲亲送达按钮与重复提交、愿望菜本餐报价／确认、整单星级／自动评价。
- 验收新增／修订：预约第0天和第7天成功、第-1天和第8天拒绝；同餐位不同请求返回已有进行中餐单；愿望不进入餐单和合计；上菜后无需亲亲或评价即可结束和再次点菜；逐菜评价可部分填写且整单留言可空。

## 5. 剩余业务问题

去重后共4组：

1. 首次家庭创建、夫妻绑定／邀请和失败恢复。
2. 亲亲价格是否允许0／小数以及最大值。
3. 待确认餐单的编辑／取消、调整被拒／全部移除／反复提案、采购备注可见性及评价修改／撤回。
4. 正式菜和愿望清单的图片必填性、妻子菜谱编辑／丈夫代点、分类／导航等界面取舍。

其他成员复杂权限、商业管理后台、AI、爱心币、等级徽章、复杂聊天、库存、社区和支付继续放到后续版本，不混入上述4组。
