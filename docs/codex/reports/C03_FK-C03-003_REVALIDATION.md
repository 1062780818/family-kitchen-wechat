## 5. 权限、安全与并发实测

真实集成脚本共执行 57 个断言，55 通过、2 失败。

### 5.1 已通过

- 可信身份：伪造 `x-user-id`、`x-family-id`、`x-role` 不改变 JWT 主体；无效 JWT 返回 401。
- 家庭隔离：两个家庭资源隔离；跨家庭菜品读写、餐单读取/状态修改均返回 403。
- 正式菜单权限：丈夫新增、修改、删除成功；妻子浏览、读取、收藏成功；妻子新增、修改、删除及正式菜图片上传均返回 403；通过 body 伪造家庭/创建者字段返回 400。
- 图片上传/读取/删除：家庭对象 key 归属正确；签名读取成功；直接未签名读取返回 403；匿名只可读 `system/*`；跨家庭签名、伪造家庭 key、路径穿越拒绝；本人删除成功，同家庭非上传者及跨家庭删除拒绝，删除后对象返回 404。
- 餐单角色与非法操作：妻子不能接单/上菜；非家庭成员不能读写；已接单/做饭中妻子不能直接取消；串行重复操作被拒绝；失败操作后状态未被越权改变。

### 5.2 失败

- 并发接单：同一 `pending` 旧状态并发发送两次接单，请求结果为 `[200, 200]`，没有一个请求得到 `ORDER_VERSION_CONFLICT`。
- 并发开始备菜：同一 `accepted` 旧状态并发发送两次开始备菜，请求结果为 `[200, 200]`，没有一个请求得到 `ORDER_VERSION_CONFLICT`。

当前 `updateWithExpectedStatus` 使用 `prisma.order.update({ where: { id, status } })`，真实 MySQL 结果证明它未满足本项目“同一旧状态竞争仅一个成功”的验收目标。重复成功还可能触发重复通知或其他副作用，不能以最终状态相同视为通过。

## 7. 修复影响回归

发现核心图片契约未同步：上传接口返回 `{ key, url }`，其中 `url` 是 900 秒签名 URL；现有小程序页面仍将 `u.url` / `r.url` 写入菜品、动态、餐单上菜图和头像字段。签名到期后，业务数据中的 URL 无法继续访问。应持久化稳定对象 key，并在展示时按当前身份换取新签名 URL，或由 C01/C02冻结另一套不会把临时 URL 持久化的合同。

另发现生产运行路径仍公开 `/auth/password-login`，且实测可创建/登录账号并签发 JWT；小程序登录页也保留该入口。该 JWT 仍受家庭权限约束，未发现可冒充已有用户或跨家庭，因此本轮定为 S2，而非把隔离测试身份误写成微信登录通过。
